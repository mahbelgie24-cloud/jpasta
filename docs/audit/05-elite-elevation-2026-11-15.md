# 05 — برنامج رفع المشروع إلى النخبة (2026-11-15)

> الفرع: `elite/design-system` · خط الأساس: `main@76c6c73` · خمسة التزامات:
> `11330bc` · `8a98502` · `3bf6ed6` · `38e13d3` · `85a5c48`
> البيئة: Node 22، PostgreSQL 17 محلي (حاوية اختبار على 127.0.0.1:54330)، Fedora Linux.
> كل بوابات هذا البرنامج خضراء محلياً؛ CI لم يُشغّل على هذا الفرع بعد (دفع + مراقبة).

## 1. الملخص التنفيذي

خمسة أطوار متتالية، كل طور بفرع التزام واحد وبواباته كاملة (مراجعة عدائية على
الـ diff، تدقيق أمني حين يلمس auth/input/شبكة، بوابة critic للتسليمات عالية
المخاطر، وتشغيل فعلي حرفي للبوابات). النتائج الأربع الكبرى:

1. **`/menu` من 4.4–4.7s LCP إلى 0.92–1.08s** (جوال LHCI) — الأسرع تجارياً في
   المشروع أصبح الأسرع قياساً.
2. **اكتشاف وإصلاح عيب إنتاجي P0**: كل حدود الحافة (ORDER/READ/AUTH_LIMIT)
   كانت تفشل مفتوحة في الإنتاج — استدعاء `limit(string)` يرفضه الـ runtime
   (الواجهة تطلب `limit({ key })`) وكان يُبتلع بصمت في try/catch لكل ملف.
   كشفه عرضي من تشغيل cross-browser، وتأكيده من وثائق Cloudflare الرسمية.
3. **تتبع الطلب للعميل صار لحظياً** عبر Durable Object بقدرة مفردة-الطلب،
   والسلة صارت تُعلِم الزبون فعلاً عند وصول طلبه المؤجل.
4. **بوابات النخبة أصبحت تقيس ولا تتجمّل**: تغطية بسقّة موثقة، دخان
   عابر للمتصفحات، hooks قبل الالتزام، CSP reporting يعمل فعلاً في Chrome.

## 2. ما نُفّذ — بالطور

### الطور A — إكمال نظام التصميم (`11330bc`، 50 ملفاً +1174/−806)

- سبعة primitives جديدة (`field/select/radio-group/toast/empty-state/skeleton/switch`)
  وكل النماذج (السلة، الموظفون، المناطق، القائمة) أعيدت عليها.
- تحقق لكل حقل في السلة (aria-invalid + منطقة خطأ دائمة + تركيز أول حقل خاطئ)،
  fieldset/legend عبر RadioCardGroup.
- مسح شامل: 274 استعمالاً لفئات ألوان بدائية → توكنات دلالية؛ **تقاعد جسر
  theme-console/theme-kitchen** من globals.css بعد وصول الاستعمالات إلى صفر؛
  توكنان جديدان (`brand-subtle`, `brand-soft`) في الثيمات الثلاث.
- إزالة إيموجي طعام من السلة الفارغة (قاعدة brand)؛ EmptyState بدلها.
- المراجع العدائي (3 P1 + 6 P2) عولجت كلها — أبرزها خطأ sed أنتج
  `bg-brand-subtle0` (سكة تقدم مختفية)، hover no-op، وتناقض تباين شارة «مالك»
  في الكونسول.

### الطور B — أداء الجوال (`8a98502`)

- تقسيمة الحزم: CartDrawer وItemSheet عبر next/dynamic (preload عند أول إضافة
  وhover)، **mount-once للسلة** بعد أن كشف المراجع P0: فك التحميل أثناء submit
  كان سيدمّر نطاق idempotency ويحوّل إعادة المحاولة إلى بيع مكرر.
- صور الصف الأول بـ `preload` + `fetchPriority="high"` (كانت lazy بما فيها
  طيّة العلوية — سبب LCP).
- إزالة أنيميشن الدخول من الـ hero: العناصر عند opacity:0 ليست مرشحة LCP —
  الأثر كان يؤجل تسجيل LCP إلى أول نافذة خمول (~4.6s)؛ أثبته تتبّع كامل.
- القياس (LHCI جوال ×3): `/menu` LCP 4413–4709ms → **921–1077ms**،
  perf 0.72–0.76 → **0.92–0.97**؛ `/` انخفض 510→491KB إجمالاً.
- الميزانيات شدّت: TBT تحذير→خطأ 900ms، perf تحذير 0.6→0.75.

### الطور C — تجربة لحظية (`3bf6ed6`، قرارك: أفضل الممارسات)

- توكن عميل (role=customer + oid) يُوقّع فقط بعد تحقق DB من زوج
  (orderId, accessToken) — قدرة مفردة-الطلب؛ حد `mint:` خاص؛ 404 مطابق للفشلين
  بلا أوراكل وجود.
- الـ DO يوسم المقابس (`staff` / `customer:<oid>`) والبث موجّه: مقبس الزبون
  لا يستيقظ إلا لطلبه؛ الـ tickle عديم البيانات دائماً.
- العميل: WS أساسي + coalescing بطرف خلفي (آخر انتقال يصل دائماً) + تعويض
  العودة للتبويب + إعادة توقيع كل 30s + الاستقصاء 4s يبقى الاحتياط (المحلي/الـ
  e2e بلا DO — السلوك كما كان).
- توست «وصل طلبك المؤجل» (مثنى عربي سليم) عند إعادة الإرسال من الطابور.
- التدقيق الأمني: «التصميم سليم، لا P0/P1» + 4 توصيات نُفذت؛ بوابة critic:
  REVISE (فقدان أحداث بلا تعويض) → أُصلح → **ACCEPT**.

### الطور D — الأمان (`38e13d3`)

- CSP reporting على الطبقين + `Reporting-Endpoints` بتنسيق Structured Fields
  (JSON هنا يُعمّي Chrome بينما Firefox/Safari يواصلان — أسوأ انقسام؛ اكتشفها

- كوكي الجلسة `SameSite=strict`؛ `/api/health` العمومي = `{ok, db, time}`
  والتفاصيل خلف Bearer CRON_SECRET (timing-safe)؛ push subscribe+delete بحد

- SECURITY.md: توثيق 2026-11-15 + **قرار توازي PII** (ليس فجوة): لوحة الكونسول
  تمرر الاسم/الهاتف/العنوان/الملاحظة لغير المالك — الحد الأدنى التشغيلي
  لتنفيذ الطلب وتوصيله؛ التصدير للمالك فقط؛ التشفير عند الراحة قائم.

## 3. العيب الإنتاجي P0 الذي كشفه البرنامج

كل استدعاءات `RateLimitBinding.limit()` كانت تمرر **سلسلة نصية** بينما الـ
runtime يطلب **كائن `{ key }`** (وثائق Cloudflare الرسمية، §Rate Limiting —
«The limit() API accepts a single argument — a configuration object with the
key field»). الـ runtime يرمي `invalid rate limit options`، وكتل try/catch
لكل ملف تبتلعه → **ORDER/READ/AUTH_LIMIT كلها فشل مفتوح في الإنتاج**، ويبقى
حد قفل الدخول في قاعدة البيانات هو الدفاع الفعلي الوحيد. أثبته سجل خادم E2E
(`server.request_error … invalid rate limit options`) وأكدته وثائق CF.
الإصلاح: شكل `{ key }` + توحيد المسار في helper واحد + تحديث الـ type stub.
نُفّذت إضافةً تجاوز `JPASTA_SKIP_EDGE_RATE_LIMIT=1` لخادم الـ e2e فقط (المجموعة
تنفذ عشرات الطلبات/دقيقة من IP واحد)، مع بقاء حد قفل الدخول DB نشطاً دائماً.

## 6. خطوات المالك بعد الدمج

1. مراجعة الـ diff للتفرع (5 التزامات) ثم الدمج في `main` — CI سيشغّل البوابات
   كاملة أول مرة على هذا الفرع (بما فيها خطتا التغطية والدخان العابر الجديدتان).
2. `sudo npx playwright install-deps webkit` محلياً إن أردت دخان webkit.
3. حساب Sentry المجاني إن أردت تفعيل المراقبة (§5).
4. بعد أول نشر: مراقبة `csp.violation` في Workers Logs أسبوعاً — أي سطر يعني
   سياسة قاسية على واقع الإنتاج أو محاولة حقن فعلية.
5. عتبات Lighthouse والتغطية **سقّة**: تُرفع، لا تُخفض.

## 7. خلاصة

الفرع رفع المشروع حيث كان القياس يكشف الفجوة: أداء الجوال للمسار التجاري أصبح
نخبوياً مقاساً لا مدّعياً؛ تتبع العميل صار لحظياً بقدرة آمنة تصميمياً ومراجعة
critic؛ الأمان أُغلق على نقاط كانت ستظهر لاحقاً (fingerprinting، xff-forgeable
keys، CSP أعمى)؛ والحدود الإنتاجية التي كانت ديكوراً (edge limits) صارت تعمل
فعلاً — واكتشافها وحده يبرر البرنامج. ما تبقى موثق أعلاه بلا تجميل: قرارات
مالك، أدوات خارجية، أو حدود نموذج قياس مُفهرسة بالأدلة.
