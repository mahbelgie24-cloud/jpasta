# 03 — التقرير النهائي (2026-11-04)

## 1. الملخص التنفيذي

المشروع كان ناضجاً في الأموال/المعاملات، لكنه حمل فجوات حقيقية: تصدير PII
تلقائي، قناة dine-in معلنة وغير منفّذة، إعادة محاولة تُحجب بعد إيقاف الطلب،
إصلاحان في PWA، وثغرات تحقق/تدقيق. أُغلقت 23 ملاحظة بأدلة واختبارات (104 →
**120** اختباراً)، مع بقاء 49 E2E خضراء وبوابات Lighthouse كما هي. لم يُضف أي
schema/migration، وكل تغيير في commit مستقل قابل للتراجع. القياسات تظهر تحسّناً
طفيفاً في أداء `/menu` الجوّال (0.78 → 0.81، TBT 372 → 271ms) وثبات LCP ضمن
البوابة، مع بقاء قيود React المعمارية موثّقة.

## 5. إجراءات تحتاج قرار/تدخّل المالك

1. **موارد الإنتاج:** إنشاء Hyperdrive + D1 + R2 IDs ووضعها في `wrangler.jsonc`،
   ثم ضبط الأسرار عبر `wrangler secret put` (لا تطبع القيم).
2. **الأسرار:** لم تُكتشف أسرار متتبعة في git. إذا كان أي سر قد شارك سابقاً
   خارج git، دوّره: `AUTH_PEPPER` يحتاج خطة `db:seed -- --provision`؛
   `REALTIME_SECRET`/`CRON_SECRET`/VAPID قابلة للتدوير مباشرة.
3. **الخصوصية:** اعتماد مدة احتفاظ وإجراء DSAR؛ تحديث سياسة الخصوصية بالأرقام.
4. **النسخ الاحتياطي:** تنفيذ استعادة تجريبية على قاعدة scratch قبل الاعتماد؛
   تقرير تشفير النسخة المرفوعة إلى GitHub.
5. **MFA/WebAuthn:** PIN-only قرار عمل موثّق؛ إن تغيّر، أضف عاملاً ثانياً.
6. **WAF/Turnstile** على مدخل الطلب عند الإنتاج إن ظهرت إساءة.

## 6. توصيات ما بعد التسليم

- إضافة CodeQL + gitleaks إلى CI (مع تثبيت SHAs) وقياس coverage تدريجياً.
- ترقية سلسلة Lighthouse/Playwright وإعادة توليد baselines في نافذة صيانة.
- إضافة RUM/OpenTelemetry وSLOs: submit p95، error rate، realtime latency.
- إضافة pagination/بحث خادمي للأرشيف عند نمو الطلبات.
- مراقبة حجم الطابور دون اتصال ونسبة فشل الإرسال.
- اختبار استعادة نسخة إنتاجية فعلياً (PITR + dump) وتوثيق زمن RTO/RPO.
- مراجعة دورية لأسعار/رسوم عبر سجل `price_changes` (بدأ الآن يشمل التوصيل
  وتكلفة المخزون).

## 7. افتراضات وأمور لم أتحقق منها

- **لم أُنشر** على Cloudflare/Neon ولم أختبر Hyperdrive/R2/D1/DO في الإنتاج؛
  التحقق يقتصر على build/CF bundle/الاختبارات المحلية.
- **لا بيانات إنتاج** ولا عملاء حقيقيون؛ كل الاختبارات على Postgres محلي
  disposable.
- **أرقام Lighthouse** مخبرية على هذا المضيف؛ قد تتغير مع الحمل/الشبكة.
- **لا مراجعة طرف ثالث** لـ ASVS؛ الخريطة تنفيذية داخلية.
- **لم أستخدم** أدوات SAST/secret-scanning خارجية (Semgrep/CodeQL/gitleaks)
  في هذه الجولة؛ الفحص اليدوي + `git grep` + `npm audit` فقط.
- **لم أختبر** stripe/بوابة دفع (غير موجودة)، ولا VAT/e-invoicing (tax=0).
- **ثغرات `npm audit` الكاملة** لم تُصلح لأنها في أدوات التطوير وتتطلب
  ترقية breaking؛ الإنتاج (`--omit=dev`) نظيف.
